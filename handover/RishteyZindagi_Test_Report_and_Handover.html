4. Images and WebP

  • New uploads: every member photo is converted on the server to WebP (max side 2048 px, quality 82, phone rotation fixed). Only the WebP is stored.
  • Old photos: 10 old JPEG/PNG photos converted with scripts/convert-photos-to-webp.ts (saved ~4.2 MB; originals kept). 4 broken placeholder PNGs from the old dev-tools were replaced with avatars. Now 116 / 116 photos are WebP.
  • Website images (hero, blog, stories): served through next/image, which sends WebP to browsers that support it (65 kB JPEG → 21 kB WebP) and JPEG to old browsers.
  • Link preview image public/og-image.jpg (1200×630) was missing — now created. Kept as JPEG because some chat apps do not show WebP previews.
  • No photo? A default illustrated avatar (by gender + religion) is shown. It is not a photo: a real photo is still required to appear in search.

10. OTP — local mein bypass kyun karte hain, aur kaise

10.1 Kyun?

Signup ke waqt member ke e-mail/mobile par 6-digit OTP jaata hai. OTP bhejne ke liye ek asli vendor chahiye — e-mail ke liye SMTP account, SMS ke liye Fast2SMS. Developer ki machine par yeh accounts/keys nahi hote (aur hone bhi nahi chahiye), isliye OTP kabhi pahunchega hi nahi aur signup aage nahi badhega. Isliye sirf local machine par OTP ko bypass karte hain taaki signup, login aur baaki features test ho sakein.

Production mein OTP hamesha ON rakho. OTP band karne se naye accounts ka e-mail/mobile "unverified" rehta hai — fake accounts ka khatra. Password reset, admin login/MFA aur contact change hamesha OTP maangte hain, chahe yeh setting kuch bhi ho.

10.2 Teen tareeke (local)

TareekaKaiseKab use karein
A. OTP policy OFF (sabse aasaan)npm run dev:otp -- off (ya npm run dev:setup -- --no-otp). Wapas ON: npm run dev:otp -- on. Same switch: Admin → Platform Settings → "Registration OTP verification".Roz ka local development
B. Development mode (OTP screen par dikhta hai)Admin → Platform Settings → One-time passwords → Development mode ON. Signup ke code screen par "Show my verification code" dabao. Production mein yeh route 404 deta hai.OTP wala screen/flow test karna ho
C. Asli e-mail OTP.env mein SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, EMAIL_FROM (local ke liye Mailpit/MailHog bhi chalega). SMS: FAST2SMS_* (see FAST2SMS_SETUP.md). Policy ON rakho.Staging/production, ya delivery test

Setting database mein save hoti hai (platform_settings → key otp.policy), restart ke baad bhi rehti hai, aur har badlav audit log mein jaata hai.

12. Deploy to a server (production) — step by step

  1. Server: Linux VPS/cloud with Node 20+, PostgreSQL 16+ (managed better), nginx/Caddy for HTTPS, a private S3-compatible bucket (AWS S3, Cloudflare R2, DO Spaces…), cron.
  2. Code: git clone … → npm ci
  3. Environment (host ke secret store mein, .env file git mein nahi): NODE_ENV=production, DATABASE_URL, APP_URL=https://your-domain, AUTH_SECRET, PAYMENT_CREDENTIALS_ENCRYPTION_KEY, ALLOWED_ORIGINS, TRUST_PROXY_HOPS=1, STORAGE_PROVIDER=s3 + S3_*, SMTP_* and/or FAST2SMS_*, CRON_SECRET. Full list: PRODUCTION_ENV_REFERENCE.md. 
    npm run check:prod-env             # must print RESULT: OK
  4. Build, database, first admin, start 
    npm run build
npm run db:migrate                 # 0000 … 0021
npm run db:seed                    # roles, reference data, PLACEHOLDER plan prices
npm run admin:create-super -- --email owner@your-domain --name "Site Owner"
npm start                          # keep running with pm2 / systemd
  5. Before opening the site: Admin → Membership Plans: set real prices · Admin → Personal Matchmaking → Settings: price + on-sale · Payment gateway live keys · OTP policy ON.
  6. nginx/HTTPS: forward to 127.0.0.1:3000, pass Host, X-Forwarded-For, X-Forwarded-Proto; block /api/v1/internal/ publicly.
  7. Webhooks: Razorpay https://<domain>/api/v1/webhooks/razorpay, PhonePe …/webhooks/phonepe.
  8. Cron jobs (npm run job -- --list): 
    */15 * * * *  cd /srv/rishteyzindagi && npm run job -- membership-expiry
5    * * * *  cd /srv/rishteyzindagi && npm run job -- membership-reminders

  9. After deploy: curl -f https://<domain>/api/v1/health/ready → 200 · signup with real OTP · upload a photo · one test payment · run a backup + restore check (BACKUP_DR.md).

13. Tests

  • npm test runs only against the database in .env.test and refuses anything that is not a local rishteyzindagi_test. It empties tables — never point it at real data.
  • A single file: npx vitest run tests/matchmaking-payments.test.ts
  • After changing src/server/db/schema.ts: npm run db:generate → new file in drizzle/ → npm run db:migrate on dev and test DB.
