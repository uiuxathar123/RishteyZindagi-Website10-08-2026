# Known limitations — Production Completion Phase

> **B18 update:** some items below are superseded (membership-plan editor built, `GatewaysPanel` removed, privacy / notification / session controls built). See `B18_KNOWN_LIMITATIONS.md` for the current list.

Severity: **P0** = data loss / security breach / cannot operate; **P1** = a core production feature does not work; **P2** = works, but with a material caveat the owner must know before launch; **P3** = minor or cosmetic.

**There are no open P0 or P1 findings.** Everything below is a P2/P3 that is either an external dependency, a documented design decision, or a follow-up. Anything not exercised against a real third party is labelled so.

## P2 — material caveats

| # | Limitation | Why / workaround |
|---|---|---|
| P2-1 | **No real third-party service has been called.** Razorpay, PhonePe, Fast2SMS, SMTP, WhatsApp Cloud API, FCM, S3-compatible storage and off-box backup were verified only against in-process mocks that reproduce the vendors' documented request/response shapes (and, for S3, against `moto` and botocore's SigV4 reference). **Status: REQUIRES EXTERNAL CREDENTIALS / NOT VERIFIED live.** | Follow the go-live checklists in `PAYMENT_SETUP.md` §6 and `FAST2SMS_SETUP.md` §5, and `BACKUP_DR.md` addendum §F. The Razorpay Checkout popup (third-party script) and the PhonePe hosted page were never rendered; only our hand-off code was exercised. |
| P2-2 | **Content-Security-Policy keeps `'unsafe-inline'` for `script-src`/`style-src`.** Next.js 14 injects inline bootstrap scripts; a nonce-based strict CSP needs a per-request nonce middleware and was not built. The CSP still blocks framing, plugins, `<base>` hijack, foreign form posts, and script/connection loads from origins other than this site and Razorpay. | Follow-up: nonce middleware + `strict-dynamic`. CSP is applied to production builds only. `CSP_IMG_SRC_EXTRA` must be set at **build** time if photos are served from another origin (today they are served through the app itself). |
| P2-3 | **No admin screen or API for membership plans.** Plans (names, prices, durations, features) are seeded rows with **placeholder prices**; `npm run db:seed` re-run resets them to the seed values. | Set real prices with SQL before launch; re-apply after any re-seed (`DEPLOYMENT_PRODUCTION.md` §3). A plan editor is a recommended next feature. |
| P2-4 | **`TRUST_PROXY_HOPS` must be configured.** With the default (0) the rate limiter keys on the left-most `X-Forwarded-For`, which a client can forge unless the edge overwrites it. | `npm run check:prod-env` warns. VERIFIED by test that `TRUST_PROXY_HOPS=1` closes the evasion. |
| P2-5 | **Auto-renewal cannot charge a card unattended.** Neither gateway integration stores a reusable mandate. The "auto-renew" flag only drives reminders and a "renewal needs your action" notice. | By design; recurring billing would need each gateway's subscription/mandate product and a separate phase. |
| P2-6 | **Account deletion keeps chat messages and payment/invoice rows.** After the recovery window the user row is anonymised (name, e-mail, phone, photos, profile) but chat messages the person sent remain in the conversation history, and financial records are retained. Old database backups also still contain the person until they age out. | Document this in your privacy policy; adjust retention to your legal advice. |
| P2-7 | **No MFA / 2FA for admin accounts.** Admin sign-in is password-only (bcrypt, rate-limited at 10/min/IP, temporary passwords forced to change). | Recommended next hardening step for a site holding personal data; restrict `/admin` at the proxy (IP allow-list or VPN) if possible. |
| P2-8 | **Off-box backup and a running scheduler are not operational until you set them up.** The scripts are verified; nothing in this repository runs them. | `BACKUP_DR.md` addendum §C/§F; `DEPLOYMENT_PRODUCTION.md` §6. |
| P2-9 | **Abandoned PhonePe payments block a new checkout for the same plan for up to 15 minutes.** The B8 duplicate-checkout guard rejects a second checkout while a payment for the plan is PENDING (15 min). For **Razorpay** the checkout page now offers *Continue to payment*, which reopens the same unpaid order (`POST /payments/:id/razorpay/resume`; VERIFIED in `tests/pcp-payments-resume.test.ts` and the browser check). PhonePe's hosted-page URL is not stored, so a member who abandons the PhonePe page must press *Check status again* and wait for the guard window (or for the payment to be closed by the `payment-reconcile` job). | Follow-up: persist the PhonePe redirect URL (valid for the order's lifetime) and reopen it the same way. |

## P3 — minor

| # | Limitation | Notes |
|---|---|---|
| P3-1 | **Validation before authorisation (400 before 403).** On endpoints that take a JSON body, an authenticated admin lacking the permission receives `400` for an invalid body before the `403`. Still no data access or state change; unauthenticated callers always get `401`. | Existing convention (`requirePermission` runs after body validation); changing it would alter frozen behaviour. Disclosed in `tests/pcp-security.test.ts`. |
| P3-2 | **Controller-level rate limiters are per-process.** The older `checkRateLimit` calls inside controllers are in-memory (per instance). The cross-instance defence is the shared Postgres policy limiter that wraps every route (`rate-limit-policy.ts`). | With several instances the per-controller limits are looser than they read; the policy limits are exact. |
| P3-3 | **Backup tooling gaps.** No `list` command for off-box objects (use the provider console; moto could not verify the list call). Off-box S3 upload is buffered and capped at 1 GiB — use `BACKUP_OFFSITE=dir` for larger databases. | |
| P3-4 | **PhonePe webhook has no documented event id.** Idempotency is by SHA-256 of the raw body; the header encoding is accepted as lowercase hex with or without a `SHA256 ` prefix. | Payment-level idempotency still prevents double activation. Confirm with PhonePe before go-live. |
| P3-5 | **Fast2SMS: delivery only, Indian 10-digit mobiles only.** Fast2SMS's own verify endpoint is deliberately not used (purpose isolation). | `FAST2SMS_SETUP.md` §1. |
| P3-6 | **Storage health is configuration-only.** `/health/ready` reports `configured`, not "reachable". | Upload a photo after deploy (`DEPLOYMENT_PRODUCTION.md` §7). There is no tool to migrate existing local-disk files to S3. |
| P3-7 | **Temporary-password gate relies on `requirePermission`.** An admin on a temporary password can still call the few routes that do not require a permission (`/admin/me`, `/admin/me/password`, `/admin/ping`, logout) — required for changing the password. Every permissioned route returns 403 until the password is changed (VERIFIED). | |
| P3-8 | **Staff & Roles appears under the "Super Admin" navigation group** even though the API permission is `staff.manage`; a non-Super role granted that permission can use the API but will not see the menu entry. | UI only. |
| P3-9 | **Legacy artefacts remain** for backward compatibility: the B8 `/admin/payment-gateways*` endpoints and the unused `GatewaysPanel` component, legacy `EMAIL_PROVIDER`/`SMS_PROVIDER`/… variables, and the `WHATSAPP` value in the OTP enum. The new screens do not use them. | |
| P3-10 | **Email/SMS deliverability is outside this codebase** (SPF/DKIM/DMARC, DLT registration, sender approval). | |
| P3-11 | **One frozen timing test is close to its budget on small machines.** `tests/performance-load.test.ts` (B13, "login p95 < 3000 ms") fires 5 concurrent logins; each bcrypt (cost 12, pure-JS `bcryptjs`) hash takes ≈ 415 ms on the 2-core build sandbox, so the floor is ≈ 2.1 s. It passed in most runs (1.7–2.7 s) and failed in two (3.0 s and 3.4 s) when the sandbox was busy. The code path was not slowed by this phase (the same test measured 2.3–2.7 s before and after). Not edited, because it is a frozen test; production hardware with more cores is faster. | If it flakes in your CI, give the runner ≥ 4 cores or raise that one threshold. |
| P3-12 | **Browser (Chromium) checks are scripts, not part of `npm test`.** `npm run smoke:ui` and `smoke:ui-gateway` need Playwright and a Chromium binary, which are deliberately **not** repository dependencies (`npm i --no-save playwright`; set `PLAYWRIGHT_MODULE` / `PLAYWRIGHT_CHROMIUM`). In them, Razorpay's popup is a **stub** and PhonePe's hosted page a placeholder — only our hand-off, confirm and return code is exercised. | `scripts/smoke/pcp-ui-check.ts`, `pcp-ui-gateway-check.ts`. |
| P3-13 | **No voluntary "change my password" screen for admins.** `POST /admin/me/password` exists and is used by the forced first-sign-in screen; there is no menu entry to change it later (a Super Admin can reset a staff password from Staff & Roles). | UI only. |
